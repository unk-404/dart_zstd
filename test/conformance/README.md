# Zstandard conformance corpus

This directory is a committed corpus of Zstandard frames produced by the
**official** [`decodecorpus`][decodecorpus] generator that ships with the
reference zstd implementation. Each frame in `zst/` is paired with the exact
plaintext in `bin/`; `manifest.json` records the generator version, per-frame
seeds and options, byte sizes and SHA-256 digests.

`test/conformance_test.dart` decodes every frame with
`ZstdDecoder(maxWindowSize: 1 << 30)` and byte-compares the result. It is
VM-only (`@TestOn('vm')`) because it reads files with `dart:io`.

## Provenance

| | |
|---|---|
| Generator | `tests/decodecorpus.c` from the reference zstd project |
| zstd version | 1.6.0-dev (`lib/zstd.h` reports `1.6.0`; checkout `v1.4.7-3087-g49cf51799`) |
| Upstream | <https://github.com/facebook/zstd> |
| Built with | `make -C <zstd-src>/tests decodecorpus` (gcc, Linux x86-64) |
| Corpus generated | 2026-10-20 UTC |
| Frames | 278 (1.67 MiB of `.zst`, 4.00 MiB of `.bin`; 5,943,868 bytes of frames + expected output, plus the manifest) |

No prebuilt binary is stored in the repository; `tool/conformance/regenerate.sh`
rebuilds `decodecorpus` from a local checkout and recreates the corpus
byte-for-byte.

## Layout

```
test/conformance/
  manifest.json          provenance, group summaries, per-frame metadata
  zst/<group>-<nnn>.zst  generated frames
  bin/<group>-<nnn>.bin  exact expected plaintext
  README.md              this file
```

## Groups and what they cover

Every frame is generated by its own process,
`decodecorpus -n1 -s<seed> -p<tmp> -o<tmp> <options>`, so any single frame can
be reproduced from the seed recorded in `manifest.json`.

| Group | Frames | Seeds | Options | Covers |
|---|---|---|---|---|
| `default` | 100 | 20261020-20261119 | `--max-content-size-log=16` | Mixed block types, random window descriptors, content sizes 0-128 KiB, contiguous sequences across multiple blocks |
| `content-size` | 50 | 20262100-20262149 | `--content-size --max-content-size-log=16` | Always-present `Frame_Content_Size`, including single-segment frames |
| `block-128k` | 50 | 20262200-20262249 | `--max-block-size-log=17 --max-content-size-log=17` | Maximum 128 KiB blocks, multi-block frames, cross-block history/offsets |
| `block-raw` | 25 | 20262300-20262324 | `--block-type=0 --max-content-size-log=16` | Forced `Raw_Block`s |
| `block-rle` | 25 | 20262400-20262424 | `--content-size --block-type=1 --max-content-size-log=16` | Forced `RLE_Block`s |
| `block-compressed` | 25 | 20262501-20262526 | `--block-type=2 --max-content-size-log=16` | Forced `Compressed_Block`s (literals + sequences) |
| `large` | 3 | 20262600, 20262615, 20262617 | `--content-size --max-content-size-log=20` | 477 KiB, 404 KiB and 268 KiB plaintext frames: long matches, many blocks, large literals/sequence sections |

Total payload before the manifest: 1,751,699 bytes of `.zst` +
4,192,169 bytes of `.bin` = 5,943,868 bytes.

### Large-group size filter

`decodecorpus` picks content sizes on a log-uniform distribution, so a random
seed with `--max-content-size-log=20` usually produces a small frame. To give
the `large` group real large-frame coverage, the generator scans consecutive
seeds from 20262600 and keeps only frames with at least 250,000 plaintext
bytes. Fifteen candidates below that threshold were skipped; the committed
frames are seeds 20262600, 20262615 and 20262617. All skipped seeds and their
measured sizes are recorded under `"skipped"` in `manifest.json`.

### Generator-invalid frames

`decodecorpus --block-type=2` can emit syntactically invalid frames for
zero-length content (it forces a compressed block even when there is nothing
to compress). Reference zstd itself rejects those outputs
(`Zstd Error (36): Src size is incorrect`), so they are not conformance
vectors and were dropped during generation. Two seeds were skipped:

| Group | Seed | Reason |
|---|---|---|
| `block-compressed` | 20262500 | `zstd -t` rejected the generated frame |
| `block-compressed` | 20262507 | `zstd -t` rejected the generated frame |

Every frame that *is* committed was accepted by the reference `zstd -t` binary
before it was added, so a decoder rejection of a committed frame is a real
conformance gap.

## Decoder requirements assumed by the test

- Frame window sizes are at most ~4 MiB (`decodecorpus` caps the window log at
  22), well below the decoder's default 64 MiB limit.
- The test uses `maxWindowSize: 1 << 30` so that any future generator change
  up to 1 GiB still decodes; frame content checksums are verified (default).
- One section of `test/conformance_test.dart` additionally covers malformed
  input (empty/truncated/corrupt magic, block overrun, oversized window
  descriptor) and edge cases (8-byte `Frame_Content_Size` with 3-byte content,
  1 KiB window, skippable-only stream).

## Regenerating

See [`tool/conformance/regenerate.md`](../../tool/conformance/regenerate.md).
In short, with a local zstd source checkout:

```bash
ZSTD_SRC=/path/to/zstd ./tool/conformance/regenerate.sh
```

To reproduce one frame from the manifest:

```bash
decodecorpus -n1 -s<seed> -p<out> -o<out> <options>   # writes z000000.zst / z000000
```
